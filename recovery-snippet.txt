GET THE CLINIC'S RECORDS OFF THE DEVICE THEY WERE TYPED ON
==========================================================

This is the only copy that still exists. Everything reachable from the
server (the VM database, the deployed seed file, this machine's Chrome
profile) holds the same 31 starter patients — checked and identical. The
patients the clinic added herself were never sent anywhere that survived,
so they can only come from the browser that entered them.

The script below is different from the earlier one: it does not look for
known names or known keys. It reads EVERY key in both web storages, EVERY
IndexedDB database and store, every cache, and (when the page is signed in)
the server copy behind /api/patients. Nothing is written or deleted.

--------------------------------------------------------------------------
STEP 1 — open the clinic address in the browser she actually used
--------------------------------------------------------------------------
Browser storage is separate for every web address. Do this once on EACH
address she used, in the same browser and same profile:

  https://clinic-ochre-seven.vercel.app
  https://site-90530542d24f4a0a8f220f83ab1afa1d.freebuff.page
  https://patient.129.154.239.74.sslip.io

On the freebuff.page address, sign in first (top-right). That is what lets
the script read her database copy.

--------------------------------------------------------------------------
STEP 2 — open the console
--------------------------------------------------------------------------
Windows / Linux:  F12, then the "Console" tab   (or Ctrl + Shift + J)
Mac:              Cmd + Option + J

If the browser blocks pasting, type "allow pasting" once and press Enter.

--------------------------------------------------------------------------
STEP 3 — paste the whole of recover-anywhere.js and press Enter
--------------------------------------------------------------------------
The file is next to this one. It downloads
    clinic-recovered-<address>-<date>.json
and prints a table plus a line like
    [clinic recovery] 34 records from https://... { signedIn: true, patients: 34 }

If no file downloads, it has still printed the data: run
    copy(JSON.stringify(window.__clinicRecovery, null, 2))
and paste that into a text file.

Do this on all three addresses and keep every file. They merge; nothing is
overwritten.

--------------------------------------------------------------------------
STEP 4 — load the files back in
--------------------------------------------------------------------------
Open the Patient Directory, press "Restore", and choose the file(s). Check
the record count in the green pill. Restore merges on registration number,
then phone, then name, so the same patient from two addresses is not
duplicated.

--------------------------------------------------------------------------
IF THE COUNT MATCHES WHAT SHE ALREADY HAS
--------------------------------------------------------------------------
Then her additions are not in that browser's storage at all. The remaining
server copy is the Cloudflare D1 database behind the freebuff.page site,
which needs her Freebuff sign-in (the script reads it in step 3 when she is
signed in). If that also returns only the starter records, no copy of the
missing records exists anywhere, and they can only be re-entered from the
clinic's paper register. Do not let anyone claim otherwise without showing
a record count from one of these sources.
